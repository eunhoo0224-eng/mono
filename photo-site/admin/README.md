# admin — 로컬 사진 도구

두 개의 로컬 도구가 있습니다. 둘 다 배포 사이트엔 포함되지 않는 **로컬 저작 전용**입니다.

- **`npm run organize`** — 사진 100~200장을 **분류(정리)**하는 도구 ⭐ (사진 많을 때)
- **`npm run admin`** — 촬영 건 하나를 **업로드 폼**으로 추가하는 도구 (몇 장 빠르게)

---

## 사진 정리 (Organizer) — `npm run organize`

사진이 많을 때(수십~수백 장) 쓰는 **분류 UI**입니다. 파일 매니저처럼 다중선택·드래그로
카테고리(컬렉션)에 나눠 담고, [게시]하면 사이트 갤러리에 반영됩니다.

### 쓰는 법
1. 사진(구글 드라이브 등에서 맥으로 내려받은 것)을 **`admin/library/`** 폴더에 넣는다.
   - JPEG/PNG/HEIC 등. 원본 크기 그대로 넣어도 됨(게시 때 웹용으로 줄임).
2. `npm run organize` → 브라우저에서 **http://localhost:4323** 열기
3. 왼쪽 **미분류**에 사진이 다 보인다. **+ 새 컬렉션**으로 카테고리를 만든다.
4. 사진을 고른다: **클릭**(하나) · **⌘/Ctrl+클릭**(여러 개 토글) · **Shift+클릭**(범위) · **⌘/Ctrl+A**(전체)
5. 고른 사진을 **왼쪽 컬렉션으로 드래그**하거나 **‘컬렉션으로 이동 ▾’** 메뉴로 담는다.
6. 컬렉션을 열면 위에서 **제목·날짜·장소·트랙·태그**를 입력하고, 사진에 마우스를 올려
   **☆ 대표**로 대표사진(썸네일)을 지정한다.
7. 다 됐으면 오른쪽 위 **[게시]** → 각 컬렉션 사진이 웹용(긴 변 2000px)으로 변환돼
   `public/photos/`에 들어가고 `content/index.csv`가 갱신된다.
8. `git add -A && git commit && git push` → 배포 사이트에 반영.

### 특징
- 작업 상태는 `admin/organize-state.json`에 저장돼 **중간에 꺼도 이어짐**.
- `admin/library/`의 원본과 작업 상태는 **git에 안 올라감**(용량 큼). 게시된 웹용 사본만 커밋됨.
- 대표사진을 지정하면 게시 때 그 사진이 목록 썸네일(001번)이 됨.

## 촬영 건 하나 추가 (Upload form) — `npm run admin`

CSV를 손으로 안 고치고 **업로드 폼**으로 촬영 건을 추가하는 로컬 도구입니다.
"프론트엔드 업로드 → 백엔드 저장(=저장소 파일)"을 그대로 구현한 것.

## 구조

- **프론트엔드**: 드래그드롭 업로드 폼 (`server.mjs`가 HTML로 서빙)
- **백엔드**: 업로드를 받아 이미지를 웹용으로 변환하고 저장소 파일에 씀 (`store.mjs`)
- **저장소(storage)**: 이 Git 저장소의 파일
  - 사진 → `public/photos/<slug>/<slug>_NNN.jpg`
  - 메타데이터 한 줄 → `content/index.csv`

즉 별도 서버·DB·클라우드 스토리지가 없습니다. 저장소가 곧 데이터베이스이고,
배포는 그 파일을 정적으로 서빙할 뿐입니다.

## 쓰는 법

```bash
npm install          # 처음 한 번 (sharp/express/multer 포함)
npm run admin        # http://localhost:4322
```

1. 브라우저에서 열고 사진을 끌어다 놓기
2. 제목·날짜·트랙·장소·태그 입력 후 "업로드하고 저장"
3. 백엔드가 각 사진을 **긴 변 2560px · sRGB · JPEG 품질 82 · GPS 제거·저작권 삽입**으로
   변환해 `public/photos/<slug>/`에 저장하고 `index.csv`에 행을 추가
4. `npm run dev`로 사이트에서 확인
5. 만족스러우면 `git add -A && git commit && git push` → 배포에 반영

## 안전장치

- **덮어쓰기 안 함**: 같은 `slug` 폴더나 색인 행이 있으면 거부
- **원본 그대로 안 올림**: 항상 웹용으로 변환(원본이 2560px보다 작으면 키우지 않음)
- **GPS 제거**: 촬영 위치 노출 방지. 저작권은 삽입(`PHOTO_COPYRIGHT` 환경변수로 변경)

## ⚠ 주의

이 서버는 **로컬 저작 전용**입니다. 인증이 없으니 **공개 인터넷에 띄우지 마세요.**
배포되는 정적 사이트에는 이 `admin/` 폴더가 포함되지 않습니다(Astro는 `src/`만 빌드).

## 왜 이런 구조인가 (백엔드 저장소 선택)

개인 사진 포트폴리오에서 사진의 "백엔드 저장소"는 보통 두 가지입니다.

1. **Git 저장소 (이 프로젝트가 택한 방식)** — 사진이 저장소 파일. 무료 정적 호스팅,
   CDN, 서버 유지비 0, 버전 관리 자동. 업로드 UI는 이 로컬 관리자가 담당.
2. **오브젝트 스토리지 + 서버(SSR)** — S3/R2 등에 저장, API 서버가 업로드 처리,
   메타데이터는 DB. 대량·다중 사용자·실시간 업로드엔 유리하지만 인증·유료 인프라·
   서버 관리가 필요. 개인 포트폴리오엔 과한 경우가 많음.

지금은 1번입니다. 나중에 2번이 필요해지면(예: 여러 명이 상시 업로드) SSR 어댑터 +
오브젝트 스토리지로 확장할 수 있습니다.
