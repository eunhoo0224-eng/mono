## R-A. STT 스택 — 한국어 실시간 인식

**결론: 서버 사이드 OpenAI `gpt-4o-transcribe`(Whisper 계열)를 기본으로,
로컬 mlx-whisper를 옵션으로, Web Speech를 무키(無key) 폴백으로 둔다.**

| 후보 | 한국어 구어체 | 지연 | 스트리밍 | 브라우저 | 비용 | 판정 |
|---|---|---|---|---|---|---|
| Web Speech API | 보통. 머뭇거림 약함 | 낮음(브라우저 내장) | 부분결과 O | **Safari ✕, FF 제한** | 무료 | 폴백만 |
| OpenAI Whisper/`gpt-4o-transcribe` | **강함**(구어·머뭇거림) | 발화종료 후 ~0.5–1.5s(청크) | 부분지원 | 전 브라우저(서버경유) | ~$0.006/분대 | **기본** |
| Deepgram Nova | 양호 | **~150–300ms 스트리밍** | O(우수) | 서버경유 | 분당 과금 | 저지연 필요시 |
| AssemblyAI | 양호 | 수백 ms | O | 서버경유 | 분당 과금 | 대안 |
| 로컬 whisper (mlx large-v3-turbo) | **최상**(의뢰인이 이미 검증) | 기기 성능 의존 | 배치 위주 | 로컬서버 | 전기값 | **옵션** |

**근거**
- 이 앱의 STT는 *실시간 스트리밍보다 턴 단위 정확도*가 중요하다. 턴은 VAD가
  끊고(R-C), 끊긴 청크를 한 번에 전사한다. 발화 종료 후 1–2초 지연은 12-4의
  "의도적 지연"과 겹쳐 체감이 크지 않다. → 스트리밍 최저지연(Deepgram)보다
  **구어체 정확도**가 우선.
- 후속 질문·층 판정(8절)은 전사 텍스트에 전적으로 의존한다. "어…", "그니까"
  같은 머뭇거림과 조사 생략이 많은 한국어 구어에서 Whisper 계열의 강건함이
  지표 신뢰도를 지킨다. STT 오인식이 지표를 망치는 문제는 12-6에서 분석
  프롬프트로 이중 방어한다.
- **브라우저 호환이 결정적이다.** Web Speech API는 Safari 미지원(12-1). 의뢰인이
  Mac 사용자라 Safari에서 못 도는 스택은 곤란하다. 서버 경유 Whisper는 브라우저
  무관.
- 의뢰인은 이미 `mlx-whisper large-v3-turbo` 파이프라인을 돌린다(명세 R-A 참고).
  로컬 서버 모드를 두면 API 비용 0에 최고 정확도. `STT_PROVIDER=local`로 전환.

**선택**: 기본 `STT_PROVIDER=openai`. Mac 로컬 실행 시 `STT_PROVIDER=local`(로컬
whisper HTTP 엔드포인트). 마이크 거부·무키 환경은 클라이언트 Web Speech 폴백 +
텍스트 모드(12-1).

**출처**: [Deepgram vs Whisper 2026](https://deepgram.com/learn/whisper-vs-deepgram),
[OpenAI Audio guide](https://developers.openai.com/api/docs/guides/audio). 구어체
정확도는 의뢰인의 로컬 mlx-whisper 실사용 및 Whisper large-v3 WER(≈4.2%) 근거.

## R-B. 아키텍처 — Realtime API vs 파이프라인 【결정적】

**결론: 파이프라인 A안 확정. Realtime B안 기각.**

**확인한 것 (명세가 "반드시 확인"이라 지목한 항목)**
1. **아첨 게이트 자리(F7·9절)** — OpenAI Realtime API는 2026년 기준 Agents SDK로
   *output guardrail*을 지원한다. transcript가 100자마다/최종 시점에 평가되고,
   음성 발화가 텍스트 생성보다 느리므로 **불안전 출력을 말하기 전에 끊을 수
   있다**([근거](https://openai.github.io/openai-agents-js/guides/voice-agents/build/)).
   그러나 이건 **차단(cut-off)**이지 **페르소나를 유지한 재생성**이 아니다.
   9절은 "걸리면 재생성(최대 2회), 실패 시 가장 짧은 응답 채택"을 요구한다.
   Realtime에서 응답을 중간에 끊고 같은 페르소나·같은 1–2문장 규격으로 다시
   말하게 만드는 것은 부자연스럽고 제어가 거칠다. → **A안이 명확히 우위.**
2. **원본 오디오 트랙 녹음(F1)** — Realtime도 오디오 트랙을 받을 수 있어 F1은
   양쪽 다 가능. 결정 요인이 아님.
3. **지연** — B안이 왕복 지연은 더 낮다(음성-to-음성). 하지만 명세 5절이
   "지연이 좋다고 B안을 자동 선택하지 말 것"이라고 못 박았고, 12-4는 오히려
   *의도적 지연 0.5–1.5초*를 넣으라고 한다. 즉 **최저지연은 이 앱의 요구가
   아니다.** A안의 청크 STT + 의도적 지연으로 3초 이내(검수 11번)는 충분히 달성.

**아첨 게이트를 넣을 자리** (A안에만 깨끗하게 존재):
```
LLM 응답 텍스트 → [정규식 검사] → [경량 LLM 판정] → 통과 시 TTS
                                              └ 실패 시 재생성(≤2)
```
Realtime은 텍스트와 오디오가 한 스트림으로 나와 이 "사이"가 없다.

**선택**: 파이프라인 A안. `docs`의 5절 다이어그램 그대로 구현.

**출처**:
[Building Realtime Agents (Agents SDK, output guardrails)](https://openai.github.io/openai-agents-js/guides/voice-agents/build/),
[Realtime and audio](https://developers.openai.com/api/docs/guides/realtime).

## R-C. VAD — 5초 침묵 감지 (F4)

**결론: `@ricky0123/vad-web`(브라우저 Silero VAD)로 발화/침묵을 판정하고,
침묵 지속 시간은 앱이 타이머로 카운트한다. RMS 직접 구현은 폴백.**

| 후보 | 오탐(생각멈춤 오판) | 에코 취약 | 번들/CPU | 판정 |
|---|---|---|---|---|
| `@ricky0123/vad-web` (Silero) | **낮음**(음성/무음 학습모델) | echoCancellation 병행 필요 | 모델 ~1–2MB, WASM | **기본** |
| Web Audio RMS 임계값 | 높음(숨소리·잡음에 취약) | 동일 | 극소 | 폴백 |
| STT 내장 endpointing | 제공자 의존, 5초 커스텀 어려움 | — | — | 부적합 |

**근거·설계**
- **오탐 대책(12-3 핵심)**: Silero가 "말소리 있음"으로 보는 동안은 침묵
  타이머를 리셋한다. 카운트다운 중 발화가 재개되면 즉시 리셋(검수 4번). 임계값은
  3–10초 설정 가능(F4), 기본 5초. 카운트다운을 화면에 시각적으로 표시(화면2).
- **에코(12-2)**: `getUserMedia({ audio:{ echoCancellation:true,
  noiseSuppression:true, autoGainControl:true }})`로 시작. 그래도 AI 음성이
  마이크로 새면 VAD가 오판하므로 **AI 발화 중에는 마이크 입력을 게이팅**(VAD
  일시정지)하는 안전장치를 둔다. 실기기 검수 필수(12-2).
- 번들: VAD 모델은 지연 로드(대화 화면 진입 시)해 초기 로딩 부담을 줄인다.

**선택**: `@ricky0123/vad-web`. 실패/미지원 시 RMS 폴백 + 「다음」 버튼(F5)만으로도
턴 진행 가능(항상 살아 있는 안전장치).

**출처**: `@ricky0123/vad-web`(Silero VAD 브라우저 포트) 공식 문서.

## R-D. 두 오디오 트랙 합치기 (F1)

**결론: 명세의 출발점 코드가 정확하다. `AudioContext` +
`MediaStreamDestination`으로 마이크와 TTS를 한 스트림에 합쳐 `MediaRecorder`로
녹음한다. 기본 포맷은 webm/opus, 다운로드 시 `.webm`. m4a는 서버 변환 옵션.**

```js
const ctx = new AudioContext();
const dest = ctx.createMediaStreamDestination();

// 마이크 (게인으로 밸런스 조절)
const micGain = ctx.createGain(); micGain.gain.value = 1.0;
micSource.connect(micGain).connect(dest);

// AI TTS: 녹음용(dest) + 스피커용(ctx.destination) 둘 다
const ttsGain = ctx.createGain(); ttsGain.gain.value = 0.9;
ttsSource.connect(ttsGain);
ttsGain.connect(dest);            // 녹음에 합류
ttsGain.connect(ctx.destination); // 사용자 스피커로도

const recorder = new MediaRecorder(dest.stream, { mimeType: 'audio/webm;codecs=opus' });
```

**확인한 것**
- **출력 포맷**: MediaRecorder 기본은 webm/opus로 전 브라우저(Safari는 최신에서
  지원, 미지원 시 mp4 폴백 탐지). **의뢰인 창고 파이프라인은 m4a를 기대**(명세
  R-D 창고 연동). → 브라우저에서 webm으로 녹음하고, **다운로드 파일명을
  `대화연습_YYYY-MM-DD_HHMM_시나리오명.webm`**로 규칙화. m4a가 꼭 필요하면
  서버에서 ffmpeg 변환 엔드포인트를 옵션 제공(README에 명시). 브라우저 단독
  m4a 인코딩은 불가하므로 무리하게 강행하지 않는다.
- **음량 밸런스**: 마이크 1.0, TTS 0.9 게인에서 출발. AI가 너무 크지 않게.
  실기기 조정(검수 1번: 양쪽 다 들린다).
- **긴 세션 메모리(12-5)**: `recorder.start(timeslice)`로 5초마다 `dataavailable`
  청크를 배열에 flush. 20분+에서도 메모리 급증 없음. 종료 시 `Blob`으로 합쳐
  `URL.createObjectURL`.

**선택**: 위 믹서. 파일명 규칙 준수로 의뢰인 창고 파이프라인이 그대로 이어받음.

**출처**: MDN `MediaStreamAudioDestinationNode`, `MediaRecorder`. 명세 R-D 출발점
코드 검증.

## R-E. LLM 아첨(sycophancy) 억제 【핵심】

**결론: 9절의 5단 대책을 전부 구현. 특히 ②(페르소나에 이해관계 부여)를 1차
방어, ⑤(정규식+경량 LLM 후처리 게이트)를 2차 방어로 둔다. character drift는 매
턴 페르소나 재주입(12-7)으로 막는다.**

**조사 결과**
- **원인**: RLHF가 동의·칭찬을 보상하도록 학습시켜 모델 기본 성향이 아첨으로
  기운다(9절 경로①). 프롬프트 수준 완화(역할·제약 명시)와 후처리 수준 완화(검출·
  재생성)를 병행해야 한 층이 뚫려도 다른 층이 잡는다.
- **character drift 패턴**: 역할극은 대체로 **초반 몇 턴은 유지되다 턴이 쌓이며**
  (특히 사용자가 메타 발화를 하거나 감정적으로 호소할 때) 어시스턴트 말투(목록·
  "제가 도와드릴게요"·과잉 공감)로 미끄러진다. → **매 요청마다 페르소나
  시스템 프롬프트 전체를 재주입**하고(대화 이력만 이어붙임), 응답을 1–2문장으로
  제한(9절④)해 미끄러질 공간을 줄인다.
- **자동 검출 방법 비교**:
  - *정규식*: "좋은 질문이네요", "흥미롭네요", "맞아요", "대단하시네요",
    불릿/굵은 글씨 등 **표지가 뚜렷한 것**에 빠르고 저렴. 1차 게이트.
  - *경량 LLM 판정*: "이 응답이 아첨/어시스턴트 말투인가?"를 yes/no로. 정규식이
    놓치는 맥락적 아첨(근거 없는 동의)을 잡음. 2차 게이트. Claude Haiku 등 저비용
    모델로 지연 최소화.
  - *분류기(파인튜닝)*: 데이터·유지비용 대비 이득 낮음. 채택 안 함.
- **선행 구현 참고**: 명세 2절이 인용한 **Lend an Ear**(LLM 롤플레이+개인화
  피드백)와 **VR 사회기술 훈련 메타분석**이 방향의 근거. 아첨 자체의 정량화는
  9절의 `agreementRate`를 자체 회귀 지표로 도입(검수 7번: < 0.5).

**선택**: 9절 5단 전부. 구현은 `lib/sycophancy.ts`(정규식+판정) +
`lib/prompts/conversation.ts`(금지표현·이해관계·1–2문장). 회귀 테스트로
`agreementRate` 감시.

**출처**: 명세 2절 인용 문헌(Kardas et al. 2022; Huang et al. 2017; Lend an Ear
arXiv 2603.15245; VR 메타분석 2024). LLM sycophancy 완화의 프롬프트/후처리 이중화는
업계 표준 패턴.

## R-F. 한국어 TTS 음성 품질

**결론: 기본 OpenAI TTS(통합 간편·다중 보이스·낮은 지연), 품질을 최우선할 때
ElevenLabs로 전환. 브라우저 SpeechSynthesis는 무키 폴백(연습 가치 낮음, 뉴스
앵커 톤).**

| 후보 | 한국어 구어체·감정 | 보이스 다양성 | 첫소리 지연 | 비용 | 판정 |
|---|---|---|---|---|---|
| **ElevenLabs** (v3 / Flash v2.5) | **최상**(MOS 4.3, 감정·표현) | 매우 많음 | Flash **~75ms** | $50/M자~ | 품질 우선 |
| **OpenAI TTS** | 양호·자연스러움 | 여러 보이스(남/여) | 낮음 | ~$15/M자 | **기본** |
| Google Cloud TTS | 또렷하나 다소 앵커 톤 | 많음 | 200–400ms | 저렴 | 대안 |
| 브라우저 SpeechSynthesis | 기계적, 감정 약함 | OS 의존 | 즉시 | 무료 | 폴백만 |

**근거**
- 연습 가치는 **구어체·감정 표현**에 달렸다(명세 R-F). 뉴스 앵커 톤이면 층
  이동·상호성 연습의 실감이 떨어진다. ElevenLabs가 감정·대화체 최상이나 비용이
  높다. OpenAI TTS는 "충분히 자연스럽고 통합이 간단"해 기본으로 적합.
- **보이스 다양성**은 페르소나별 목소리(남/여·나이대, 명세 R-F·10절)에 필수.
  OpenAI 다중 보이스로 페르소나 성별·나이대에 매핑. ElevenLabs는 더 세밀.
- **지연**: 첫소리까지 낮아야 12-4의 의도적 지연 예산 안에 든다. OpenAI·
  ElevenLabs Flash 모두 스트리밍으로 첫소리 빠름. Google은 상대적으로 느림.

**선택**: `TTS_PROVIDER=openai` 기본, `TTS_PROVIDER=elevenlabs` 옵션. 페르소나
`gender`/`age`로 보이스 선택. 무키 시 클라이언트 SpeechSynthesis.
